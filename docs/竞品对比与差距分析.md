# 一、结论先行

1. 主流开源方案的检索能力已相当成熟(混合检索、重排、多种切分、OCR、知识图谱),我方在检索通道完整性上曾存在差距 —— 本次已补齐混合检索(BM25 + 向量 + RRF 融合)与表格结构化解析。
1. 但在"制度治理"这条主线上,主流方案普遍是空白:文件编号/生效期/失效期、被替代版本自动废止、跨知识库冲突检测、制度版本差异判别 —— 这些我们独有。
1. 权限与审计在多数项目中属于收费版:Dify 的细粒度 RBAC 与审计日志、MaxKB 的 RBAC/操作日志、FastGPT 的文件级权限与团队空间、PrivateGPT 的 RBAC/审计 均标注为商业版;RAGFlow 仅有登录审计;AnythingLLM 权限到工作区级、无部门模型。我方在开源形态下即提供部门级可见性 + 九类操作审计。
1. 部署形态差异显著:RAGFlow 最低 4 核/16GB/50GB,多容器(ES/MySQL/MinIO/Redis);FastGPT 6+ 服务;PrivateGPT 需 Postgres+RabbitMQ+Redis+Celery+Qdrant。我方为单机单进程 + 本机 Ollama,8GB 显存笔记本即可运行 —— 这正是中小企业场景的落点。
1. 评测能力普遍缺失:RAGFlow 仅检索测试、Dify 无内置评测、AnythingLLM 未发现评测工具、MaxKB/FastGPT 评测为收费版;Verba 的"rerank 与评测"长期停留在 planned。我方本次已自建可复现评测集与评测接口(hit@1/hit@3/MRR/引用命中/事实命中/拒答正确率)。
1. 若干项目已停更或转型:Verba 已归档(README 明确不再更新)、Quivr 转为纯 Python 库且默认分支自 2025-06 休眠、Langchain-Chatchat 最新 release 停在 2024-07。

# 三、我方优势(可经得起追问的三条)

1. 制度治理能力是稀缺项:全表 8 个竞品中,没有任何一个提供"生效期/失效期 + 被替代自动废止 + 跨库冲突检测 + 版本差异判别"。RAGFlow 最接近的是"Empty Response"(数据集内作答)与登录审计,但都没有版本语义。
1. 合规能力在开源形态即可用:权限与审计在 Dify/MaxKB/FastGPT/PrivateGPT 中均为商业版或不存在;我方在开源代码内实现部门可见性、越权拦截(403/deny)、九类操作审计与部门范围约束。
1. 部署与资源匹配中小企业:竞品普遍需要 16GB 内存起步或多服务编排;我方单进程 + 4.7GB 模型,在 8GB 显存办公笔记本上实测单次问答 8–15 秒(评测集 17 题平均 7.9 秒)。

# 六、定位结论

与 RAGFlow、Dify 等通用平台相比,我们不追求"功能最多",而是把制度治理这一垂直场景做透:

在开源形态下同时提供库级物理隔离、制度版本与生效期治理、跨库冲突检测、部门权限与审计留痕,并以单机私有部署适配中小企业的资源与合规约束;

检索侧已补齐主流方案普遍具备的混合检索与表格解析,并额外提供可复现的本地评测集(竞品普遍缺失或被商业版锁定)。
